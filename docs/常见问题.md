# 常见问题

## 是 Air75 也能用吗？

目前只实际验证 NuPhy Node75 LP 的 2.4G 接收器 `19f5:2620`。不是通用 NuPhy 控灯器，不能据此保证 Air75 或其他型号可用。

## 为什么没有彩色、呼吸或流光？

当前方案走接收器的标准 Boot 键盘指示灯输出，只能控制左上角点阵第 1、3、5 列的白灯同时亮灭。NuPhyIO 中可选的原生灯效不等于此无线通道能够触发这些效果。目前支持慢闪、快闪、常亮。

## 灯不亮，但我还能正常打字

先确认 Fn + 4 的 2.4G 模式和接收器。打开接入页，检查后台运行和输入监控权限，然后点“重新检查”，用菜单的灯效预览排除 Hook 问题。预览可用但对话不触发时，核对 7 个 Hook 已配置／可信／启用，开始新会话并观察“最近事件”。

重连重试间隔约 2 秒。睡眠、固件自己的提示和其他写入指示灯的程序可能覆盖显示；避免同时运行其他状态灯控制器。拔掉接收器时无法发送恢复命令，重新连接后再试。

## 软件说找不到 Python 或 Codex CLI

用 `python3 --version` 确认 Python 为 3.8+；推荐 Homebrew 的 `/opt/homebrew/bin/python3`。安装器会记录使用的 Python 路径；移动或卸载这个 Python 后，请重新安装／修复接入。

用 `codex --version` 和官方 CLI 确认已安装并登录。菜单栏应用不会读取你的交互式 shell 配置；如果自定义安装位置无法被发现，可在已有 `~/Library/Application Support/Node75Codex/menubar-config.json` 中把 `codex` 设为官方 CLI 的实际绝对路径，保留其他字段，再重新检查。不要填入凭据。软件也会尝试查找桌面版自带的 CLI；桌面版布局变化可能导致这个路径失效。

## 只有周额度，5 小时是“暂未提供”

官方接口可能只返回一个窗口。程序根据窗口长度识别额度，不把周额度误当 5 小时，也不把缺失数据显示为 0%。额度数字后出现 `*` 时是过期缓存或刷新失败；可检查登录／网络后手动刷新。

## Hook 已配置，可信／启用仍是未知

这些数量来自官方 `hooks/list`。CLI 不可用、接口版本不兼容或查询失败时，配置文件里有定义并不能证明它已获信任。点官方审阅入口，在 CLI 输入 `/hooks` 核对；软件不会自行写入信任记录。

## 为什么提问没有快闪？

支持权限请求和 `request_user_input`／`request_user_input_async` 这两种提问工具。普通正文问句没有独立 Hook 等待事件，当前无法识别。不同 Codex 版本的 Hook 行为也可能变化。

## 会改变 Caps Lock 或记录我的按键吗？

不会发送 Caps Lock 或其他按键，只写指示灯报告。点阵显示任务时暂时不能同时表示大写锁定；空闲与正常退出时按系统状态尝试恢复。输入监控权限用于打开 HID，软件没有按键日志功能。

## 我退出了窗口，灯为什么还闪？

窗口、菜单栏和灯光后台是独立层次。关闭窗口不退出菜单栏；退出菜单栏也可以保留灯光后台。临时关闭后台后下次登录仍会启动。长期停用用“解除 Codex 接入”，完整卸载见 [使用说明](使用说明.md#停用与卸载)。

## macOS 拒绝打开安装包

公开包使用本地签名，未经 Apple 公证。确认来源后按 macOS 的“隐私与安全性”提示处理，或者从源码构建；不需要关闭系统安全功能。程序启动许可、HID 输入监控许可和 Codex Hook 信任是三种不同检查。

## 怎么反馈问题？

在 GitHub Issues 描述复现步骤、macOS／CPU／键盘固件／接收器固件／Codex CLI 版本，并说明预览是否可用、7 个 Hook 状态和最近事件是否更新。分享日志前删去个人路径、会话标识等私人信息，不上传 Codex 凭据或完整配置文件。
